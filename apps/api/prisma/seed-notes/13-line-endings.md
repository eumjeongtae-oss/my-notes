내용은 그대로인데 파일 19개가 "수정됨"으로 잡혔다. 원인은 줄바꿈 문자였다.

## 줄바꿈 문자

| 이름 | 문자   | 쓰는 곳          |
| ---- | ------ | ---------------- |
| LF   | `\n`   | 맥, 리눅스(서버) |
| CRLF | `\r\n` | 윈도우           |

## 무슨 일이 있었나

1. 윈도우 git은 `core.autocrlf=true`라서 파일을 꺼낼 때 **CRLF**로 바꾼다
2. Prettier는 포맷하면서 **LF**로 바꾼다
3. git 입장에서는 줄바꿈만 바뀐 파일들이 전부 "수정됨"

## 해결: .gitattributes

```
* text=auto eol=lf
```

모든 텍스트 파일의 줄바꿈을 **LF로 고정**한다. 커밋할 때마다 뜨던 `LF will be replaced by CRLF` 경고도 사라졌다.

> 윈도우에서 개발하는 팀은 프로젝트 시작할 때 거의 항상 이 파일부터 넣는다.
> 리눅스 서버(EC2)에 배포할 때 스크립트가 깨지는 문제도 예방한다.

## 비슷한 함정: pnpm과 폴더 이름

pnpm은 윈도우에서 `node_modules` 링크를 **절대 경로**로 만든다.
폴더 이름을 바꾸면 링크가 깨지므로 `pnpm install`을 다시 실행한다.
