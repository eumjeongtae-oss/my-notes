DB 테이블은 엑셀 시트다. 노트와 시리즈는 외래 키 series_id로 연결된다.

## 용어

| DB 용어     | 엑셀 비유                         |
| ----------- | --------------------------------- |
| 테이블      | 시트 하나                         |
| 행(row)     | 한 줄 = 노트 하나                 |
| 열(column)  | 칸 = 제목, 본문…                  |
| 기본 키(PK) | 각 줄의 고유 번호. 절대 안 겹친다 |
| 외래 키(FK) | 다른 시트의 고유 번호를 적어둔 칸 |

## 1:N 관계

시리즈 1개에 노트 여러 개. **연결 고리는 N 쪽(노트)에만** 있다.

| id  | title           | series_id | series_order |
| --- | --------------- | --------- | ------------ |
| 1   | App Router 기초 | 1         | 1            |
| 2   | 서버 컴포넌트   | 1         | 2            |
| 3   | 오늘 회고       | _(null)_  | _(null)_     |

시리즈 쪽에 `note_ids: "1,2,5"`처럼 적으면 노트가 늘 때마다 고쳐야 하고 검색도 어렵다.

## 외래 키 제약

DB가 "`series_id`에는 실제로 있는 시리즈 id만 적을 수 있다"는 규칙을 지켜준다.
코드에서 실수해도 데이터가 엉키지 않는다.

- `ON DELETE SET NULL`: 시리즈를 지우면 노트는 남고 `series_id`만 비운다
- `CASCADE`였다면 시리즈를 지울 때 노트까지 다 지워진다

## 인덱스

책 뒤의 **찾아보기**. 없으면 DB가 처음부터 끝까지 다 뒤진다.

- `[updated_at, id]`: 홈 정렬, 무한스크롤
- `[series_id, series_order]`: 시리즈 안의 순서
