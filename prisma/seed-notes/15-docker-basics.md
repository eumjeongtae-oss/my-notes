MySQL을 내 컴퓨터에 설치하지 않고 Docker 컨테이너로 띄웠다.

## 세 단어

| 단어     | 비유                   | 이 프로젝트                |
| -------- | ---------------------- | -------------------------- |
| 이미지   | 설치 파일 (레시피)     | `mysql:8.4`                |
| 컨테이너 | 실행된 프로그램 (요리) | `my-notes-mysql`           |
| 볼륨     | 외장 하드              | `mysql-data` (노트 데이터) |

`compose.yaml`은 **"이런 컨테이너를 이렇게 띄워 줘"라고 적은 주문서**다.

## compose.yaml 한 문장 요약

> MySQL 8.4 이미지로 `my-notes-mysql` 컨테이너를 만들고, 비밀번호는 `.env`에서 가져오고, 내 컴퓨터 3306번 문으로 연결하고, 데이터는 `mysql-data` 외장 하드에 저장하고, 5초마다 건강 검진을 해줘.

## 포트

- 포트는 컴퓨터의 **문 번호**다. Next 개발 서버는 3000, MySQL은 3306
- `"3306:3306"` = 내 컴퓨터 3306 → 컨테이너 3306 (왼쪽이 내 컴퓨터)

## healthcheck

- 컨테이너가 켜졌다고 MySQL이 바로 일할 수 있는 건 아니다
- `-h 127.0.0.1`(TCP)로 확인해야 초기화용 임시 서버를 "준비 완료"로 착각하지 않는다

## 명령어

| 명령어                        | 의미                                          |
| ----------------------------- | --------------------------------------------- |
| `docker compose up -d --wait` | 띄우고, 뒤에서 돌리고, 건강해질 때까지 기다림 |
| `docker compose down`         | 끄기 (데이터 유지)                            |
| `docker compose down -v`      | ⚠️ **데이터까지 삭제**                        |
| `docker compose ps`           | 상태 보기                                     |

## MySQL 설치는 필요 없다

컨테이너 안에 MySQL 서버와 `mysql` 명령어가 다 들어 있다. 직접 설치하면 3306 포트가 충돌한다.
DBeaver 같은 도구는 **보는 창(클라이언트)**일 뿐이다.
